# نطاق مرآة | NITAAQ Mirror

تطبيق أندرويد أصلي (Kotlin) لعرض شاشة جوال أندرويد والتحكم فيه باللمس المباشر من جوال آخر على شبكة Wi-Fi نفسها، بلا حساب ولا خادم ولا اشتراك.

- **دليل الإعداد للجهازين (عربي):** [docs/SETUP_AR.md](docs/SETUP_AR.md)
- **التقرير: ما يعمل، وما اختُبر، وما يحتاج تجربة فعلية، وحدود أندرويد:** [docs/REPORT_AR.md](docs/REPORT_AR.md)
- **تعليمات البناء وإصدارات الاعتماديات:** [BUILD.md](BUILD.md)
- **ملف APK (إصدار اختبار):** [dist/](dist/)

## البنية باختصار

```
 المضيف (Motorola)                                         المتحكم (Note10+)
 ┌───────────────────────────────┐   TLS 1.3 (TCP, LAN)   ┌──────────────────────────────┐
 │ MediaProjection               │  ───── فيديو H.264 ──▶ │ MediaCodec decoder (HW)      │
 │  → VirtualDisplay (mirror)    │                        │  → SurfaceView (بلا نسخ CPU) │
 │  → MediaCodec encoder (HW)    │                        │                              │
 │  → طابور إرسال «الأحدث أولًا»  │  ◀── لمس/أزرار/نص ──── │ لمس مباشر + شريط تحكم        │
 │ AccessibilityService          │                        │                              │
 │  → dispatchGesture (مستمر)    │                        │                              │
 │ Foreground service + إشعار    │                        │                              │
 └───────────────────────────────┘                        └──────────────────────────────┘
```

| الطبقة | الملفات |
|---|---|
| البروتوكول والإطارات | `proto/Protocol.kt` |
| منطق نقي مختبر على JVM | `core/` (تحويل الإحداثيات، تخطيط الإيماءات، حالة الاتصال، الاقتران، الجودة، الشهادة) |

| المتحكم | `ctrl/RemoteSession.kt`, `ctrl/VideoDecoder.kt`, `ctrl/RemoteActivity.kt`, `ctrl/ControllerActivity.kt`, `ctrl/ScanActivity.kt` |

## لماذا هذا المسار للنقل (وليس WebRTC)

قُيّم WebRTC أولًا كما طُلب. مكتبة Google الرسمية الجاهزة لأندرويد (`org.webrtc:google-webrtc`) لم تعد تُنشر أو تُحدَّث، والبدائل المتاحة نسخ مُعاد بناؤها من أطراف أخرى. كذلك يضيف WebRTC قرابة 10MB لكل معمارية، ويحتاج قناة signaling، ويستخدم jitter buffer يضيف تأخيرًا مقصودًا. وأهم مزاياه (عبور NAT وتحمّل الإنترنت) غير مطلوبة في النسخة الأولى المحلية.

المسار المختار هو مسار واحد بأسلوب scrcpy: **ترميز H.264 عتادي → TLS 1.3 فوق TCP داخل الشبكة المحلية**، مع:
- طابور إرسال يقدّم حداثة الصورة: إذا تأخر الإرسال أكثر من 120ms تُرمى الإطارات القديمة ويُطلب إطار مفتاحي.
- مخزن إرسال TCP محدود (192KB) حتى لا تختبئ صورة قديمة في النواة.
- معدل بت تكيفي، وحد أقصى لمعدل الإطارات على المرمِّز (`KEY_MAX_FPS_TO_ENCODER`).
- وضع فك الترميز منخفض التأخير (`KEY_LOW_LATENCY`) حين يدعمه العتاد، وعرض أحدث إطار فقط.

العيب المعروف لهذا المسار: TCP يعيد إرسال الحزم المفقودة بدل تجاوزها. لذلك «فقد الحزم» لا ينطبق، وتعرض لوحة التشخيص عدد الإطارات المُسقطة بدلًا منه.

## الترخيص والمراجع
استُلهمت فكرة الاستخدام من AirDroid/AirMirror، وفكرة المسار التقني من scrcpy وRustDesk، دون نسخ أي كود أو هوية أو أصول منها. الكود هنا مكتوب لهذا المشروع. الاعتمادية الوحيدة وقت التشغيل هي ZXing core 3.5.3 (Apache-2.0) لقراءة وتوليد رمز QR، إضافة إلى Kotlin stdlib (Apache-2.0).
